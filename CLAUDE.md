# Inkwest

AI-powered investigation assistant — chat interface backed by Claude that brokers scoped, read-only access across connectors (Kubernetes/kubectl, AWS, GitLab) plus Coralogix observability via MCP, to investigate and correlate issues across systems.

## Tech Stack

- **Backend**: FastAPI + SQLAlchemy async + PostgreSQL + asyncpg
- **Frontend**: React + TypeScript + Vite + Zustand + Tailwind CSS
- **AI**: Claude Code CLI + sandboxed inkwest-agent (Bedrock Converse) + sandboxed opencode CLI; engine-dispatched, no `AI_PROVIDER`
- **Auth**: OIDC (optional) with JWT session tokens, dev mode auto-login

## Architecture

- **Orchestrator pattern**: each engine has its own orchestrator yielding `ChatEvent` for WS streaming; `get_orchestrator()` is a single per-turn engine dispatcher (no `AI_PROVIDER` — engine is the sole driver)
- **Cancellation**: orchestrators accept `cancel_event: asyncio.Event` checked at loop boundaries (before API call, after response, before/during tool execution)
- **Dependency injection**: FastAPI `Depends()` for `get_current_user`, `require_admin`, `get_db`, `check_cluster_access`
- **Real-time sync**: PostgreSQL `LISTEN/NOTIFY` → `pubsub.py` → per-WS `asyncio.Queue` fan-out
- **Tool execution**: async subprocess kubectl with validation, timeout, output truncation
- **WS dual-task pattern**: `chat.py` runs receive loop + process loop as concurrent tasks so `stop` messages arrive during streaming
- **Model selection**: admin-managed registry (`model_registry` table + `model_registry.py`) over a live-discovered catalog. `model_catalog.py` is pure discovery (Anthropic API, Bedrock via aws CLI incl. open-weight models when the `bedrock_include_open` flag is set; the CLI's backend is resolved from **backend settings** — `aws_bearer_token_bedrock`/AWS creds ⇒ Bedrock, else `anthropic_api_key` ⇒ Anthropic — never `sandbox.env`, so the LLM broker can strip the key from the sandbox without breaking discovery) with pricing resolved per turn as **live Bedrock Price-List → static table → default** (`pricing.get_model_pricing`): `pricing_live` fetches the public, unauthenticated AWS bulk Price List at catalog-refresh and maps it to model IDs via `pricing.price_match_keys`; the static table covers Anthropic (absent from the Bedrock Price List) and is the offline fallback. Vendor grouping/routing tags come from `model_catalog.bedrock_vendor` (the namespace, verbatim — no allowlist). The registry owns the admin-facing layer: which models are enabled, the default, per-model metadata (endpoint/arn/options), and pricing overrides, plus operator-added `source='custom'` rows the discovery filter doesn't surface. Discovered models with no row are synthesized on read (disabled; provider re-derived from the ID, priced when the live list or static table knows them). Resolution per turn: session pin → registry default → newest enabled → newest available, each validated against the current catalog so a backend/catalog change degrades gracefully. Admin endpoints: `/api/admin/settings/model` (GET/PUT) + `/api/admin/settings/model/refresh`, and the sibling `/api/admin/models` CRUD (`POST`, `PUT|DELETE /{model_id}`). Registry + catalog cached in-process (mirrored in memory post-write, like `app_settings.py`): replicas pick up changes on restart/TTL only. Switching a session's model invalidates its Anthropic prompt cache (first turn after re-pays full input)
- **Non-Anthropic Bedrock models in chat**: non-Anthropic Bedrock models (Llama/Mistral/Nova/DeepSeek) can't go through the Anthropic SDK, so they run on the **`inkwest-agent`** engine — the sandboxed worker's Bedrock **Converse** loop (`inkwest_agent/converse.py` + `loop.py`, boto3, translating Anthropic content blocks ↔ Converse blocks at the API boundary only). The loop caches opportunistically: `cachePoint` markers on system/tools/last-message, degraded per captured pre-inference rejection signatures — `ValidationException` + "extraneous key [cachePoint]" (Nova refuses the tools placement) drops the tools marker only and keeps caching; `AccessDeniedException` + "prompt caching" (no caching at all) strips every marker; each rejection = one silent free retry, the memo holds for the rest of the turn. `get_orchestrator()`'s per-turn dispatcher (`ai_client._dispatch_engine`) resolves the engine via `engines.engine_for_turn` from the resolved model's registry provider tag (`provider_speaks_messages()` → Claude on the CLI; every other per-vendor tag → the agent), falling back to the `is_anthropic_model` ID heuristic for models with no registry row. Registry provider tags are per-vendor (`anthropic`/`amazon`/`meta`/`mistral`/`cohere`/`ai21`/`deepseek`/`stability`, derived via `model_catalog.bedrock_vendor`; legacy `bedrock`/`bedrock-open` still accepted). The whole-Bedrock catalog (all vendors) and the admin all-vendors toggle are gated on **any agent engine** (`inkwest-agent` or `opencode`) being enabled (`AGENTIC_ENGINES` → `engines.open_catalog_enabled()`, see `app/services/engines.py`). A second agent engine, **`opencode`**, runs the [opencode](https://opencode.ai) terminal coding agent non-interactively in the sandbox (`orchestrator_opencode.py`, `ai_cli_client.execute_opencode`/`parse_opencode_response`) — parity with `claude-cli` (spawn → NDJSON→`ChatEvent` → resume via `--continue` over a per-conv data-dir mount), giving native bash/file tools over Bedrock all-vendors, with MCP (→ `opencode.json` `mcp`) + skills (→ `AGENTS.md` index) materialized per turn and an abnormal-exit container teardown to reap child processes
- **LLM auth broker** (`llm_broker_enabled`, sandboxed engines): zero real Bedrock secret in the sandbox. The sandbox holds only a short-lived, opaque **per-turn grant** in `AWS_BEARER_TOKEN_BEDROCK` (in-process store `llm_proxy_token.py`, minted at turn start, BURNED in the orchestrator `finally`). The broker route `app/api/routes/llm_proxy.py` has two legs: data plane (`POST /api/llm-proxy/model/{id}/{op}`) verifies the grant, restricts to enabled registry models/ARNs (+ their inference-profile ids) + allowed Bedrock ops — **fail-closed**: no enabled rows ⇒ nothing invocable (unlike the default-open picker; the broker is a credential gate) — swaps in the backend-held real bearer (`settings.aws_bearer_token_bedrock`), streams to `bedrock-runtime.<region>` under a total wall-clock cap; control plane (`GET /api/llm-proxy/{inference-profiles|foundation-models}`, dot-segments rejected) forwards to `bedrock.<region>` so Claude Code can resolve a model to its regional inference profile (required in regions like eu-west-1 — without it the bare-id invoke 403s). Pure header swap, no SigV4 (both the CLI's `ANTHROPIC_BEDROCK_BASE_URL` and the agent's boto3 `endpoint_url` send `Authorization: Bearer …`; `x-amz-*` SigV4/credential headers from the sandbox are stripped); shared streaming-proxy primitives (body cap, hop-by-hop strip, teardown) live in `app/api/routes/_proxy_stream.py`, reused by `mcp_proxy.py`. Wiring (`llm_broker.py`): all sandboxed engines (CLI, inkwest-agent, opencode) inject the grant per turn via `docker exec -e` (overriding `sandbox_env_file`), each carrying the base URL its own way — the CLI via `ANTHROPIC_BEDROCK_BASE_URL`, the inkwest-agent via `bedrock_endpoint_url` on the TurnSpec (protocol v5; the orchestrator omits unset/None scalars from the wire spec so an older agent image still parses a broker-off turn), opencode via its `opencode.json` `provider.amazon-bedrock.options.baseURL`. With the broker on, the CLI is forced onto the registry default when a session has no model pin (else it'd invoke its built-in default and 403). Broker host = `llm_broker_base_url` when set (in-pod sentinel, `--add-host`-mapped, so model traffic never hairpins through the shared ALB and its 60s idle cut — ), else the `mcp_proxy_base_url` host (squid allowlist + `--add-host`) as before. Grant store is in-process + hard-capped (single-replica assumption; `main.py` fail-fasts on `WEB_CONCURRENCY>1`). Off by default ⇒ today's behavior (real bearer in `sandbox_env_file`). **Broker metering (budget accuracy)**: the data plane passively tees the forwarded bytes (`llm_metering.MeteringTee`) and persists one `usage_records` row per Bedrock call post-stream (`source='broker'`, cache tokens from the wire — `invocationMetrics` on invoke-stream is the billed truth, `input_tokens` = FRESH input everywhere, cache rides its own columns), grant claims carry `engine`+`turn_id` for attribution/rollup (`GET /api/me/usage/turns`), and broker-on turns skip the engine-side budget row (session stats + Message token stamps stay engine-fed); metering failures bump `inkwest_llm_metering_failures_total` and never touch the stream. See `docs/llm-auth-broker.md` + `docs/BUDGET.md` (2026-07-04 cutover)
- **MCP per-tool permissions**: engine-agnostic moderation at the proxy (`mcp_proxy.py` — all three engines' MCP traffic funnels there; `--dangerously-skip-permissions` stays, it governs built-in tools only). Policy = scope (global `user_mcp_tool_policy` / conversation `session_mcp_tool_policy`, `tool='*'` row = server default) × verdict (allow/deny/ask); `mcp_policy.resolve_verdict` precedence conv/tool → conv/* → global/tool → global/* → **ask** (system default). The proxy parses JSON-RPC `tools/call` (single + batch), denies with a -32001 JSON-RPC error, and on `ask` **holds the request** on an in-process Future (`mcp_ask_store.py`, 60s → deny, fail-closed, single-replica like `llm_proxy_token`): targeted WS frame `mcp_tool_ask` to the asking user's tabs only (`chat.send_to_user_in_session` — peers/guests never see it), decision via `POST /api/mcp/ask/{ask_id}`, reload-rehydrate via `GET /api/mcp/ask/pending`, `mcp_tool_ask_resolved` clears other tabs; a late Allow is dropped if the sandbox client already disconnected (no behind-the-back execution). Policy resolution failure fails OPEN (credential broker stays the hard boundary) but the ask flow fails CLOSED. Tool lists enumerated server-side (`mcp_tools.py`, mcp SDK is a core dep — image rebuild on deploy) into `mcp_server_tools` cache, `GET /api/mcp/{key}/tools` (+`?refresh`); UI = 5-option editor (`McpToolPolicyEditor`, conversation popup + Settings `mcp` tab, optimistic writes) + in-bubble ask decisions: a held call renders an Allow/Deny **split-button bar inside the matching transcript `ToolCallCard`** (scopes once / this conversation / always-global; broader scopes fetch→merge→PUT the per-server full-state policy through the shared `runPolicySave` chain in `store/mcpPolicy.ts`, then bump `useMcpPolicyVersion` so open editors refetch; the ask frame carries `session_id` so a conversation-scope write targets the ask's own session). Cards claim asks via a **per-card sync ref** (`useRef`) + store `claimedAsks` (state there loops: claim→release ping-pong ⇒ white page); `McpAskNotice` inline banner stack (tool name only — args already visible via tool_start) is the **fallback** for asks with no visible card (mid-hold reload) and rehydrates on mount/session-switch/WS-reconnect
- **Combined prod image**: root `Dockerfile` builds the SPA (`VITE_API_URL=""` → same-origin) and bakes it into `/app/static`; `mount_spa()` in `app/main.py` serves it with index.html fallback (404-guarded for `api/`, `assets/`, `ws/`), `Cache-Control: no-cache` on index, gzip + security headers. Dev unchanged (no `static/` dir → JSON root endpoint). CI builds it, no variants
- **Frontend backend-down resilience**: AWS/ALB answers 502/503/504 (or the network fails) while the backend restarts/redeploys. `services/api.ts::fetchWithRetry` (every `fetchAPI` caller + the raw attachment fetches route through it) retries those + network errors for **all verbs** with jittered capped-exponential backoff (`lib/backoff.ts::jitteredBackoff`, ~12 attempts ≈ up to a minute). Client timeouts split by idempotency: **GET/HEAD** get a 30s abort-**and-retry** timeout (a hung read is safe to replay); **mutations** get a 5min timeout-to-**fail** (`MUTATION_TIMEOUT_MS` — reject, never replay) so a slow AWS enumerate/STS-mint isn't killed but a truly hung POST still surfaces. Attachment transfers opt out of timeouts entirely. The four WS reconnect loops (`ChatWebSocket`, `useSyncSocket`, `useEgressSocket`, `useSharedSocket`) reconnect **uncapped** (delay capped 30s + jitter) until a 10min wall-clock budget (`lib/backoff.ts::createReconnectBudget`, reset on a successful open / tab-foreground) is spent; each stops on its own terminal/clean close codes (1000 app-close; 4001 auth→redirect; chat 4004/4010/4011; egress 4003; shared 4004/4012 revoked, 4009 guest cap → stale) and aborts its in-flight `fetchWsTicket` (shared: its transcript read) on disconnect/unmount. The shared endpoint **accepts before closing** with those codes — a pre-accept close goes out as HTTP 403 and reaches the browser as 1006. `useSharedSocket` re-reads the transcript on every open (the server replays only the turn in flight) and again at `done` when a read was in flight, so a turn that ended during the outage is never lost. A refcounted `store/backend.ts::useBackendStore` drives `BackendBanner`: amber "reconnecting…" while any HTTP call backs off (cleared on the first reachable app response or WS `onopen`), and — only when the **sync** socket (the app-wide heartbeat) exhausts its budget — a red **"reload"** prompt (`gaveUp`, sticky until page reload; chat/egress give up quietly). **Trade-off**: a retried non-idempotent call (502/504/network) can rarely double-apply server-side — accepted; durable fix is server idempotency keys on the AWS mint/grant routes. **Single connectivity surface**: `BackendBanner` is the *only* connectivity message inside the shell (precedence `gaveUp` red-reload > `unavailable` amber); the shell-less `/shared/:token` page carries its own header indicator from `useSharedSocket`'s `connection` (amber "Reconnecting…", red reload link once `stale`). The chat header `ConnectionStatus` is the lone chat-scoped indicator — an icon-only dot (`title`/`aria-label`, non-live) that **yields** to the banner: while `unavailable || gaveUp` it shows a neutral dot instead of echoing "reconnecting"/"disconnected", surfacing the chat-socket state on its own only when the backend is up but the stream blipped. The in-view `ReconnectingBanner` was removed as a pure duplicate of that badge's `isReconnecting` flag. The banner additionally hosts a **non-connectivity surface**: a dismissible red **5xx strip** — `fetchAPI` (+ the raw attachment fetches) reports any app-emitted ≥500 (gateway 502/503/504 excluded, even after retry exhaustion — that's the amber banner's story) to `store/backend.ts::serverErrors` before throwing, deduped by `METHOD /path` with UUID path segments collapsed to `:id`, capped at `MAX_SERVER_ERRORS` (oldest evicted), self-healing on the route's next 2xx, so best-effort `catch {}` callers can't bury a persistent backend bug
- **Web Push on share** (spec 003): `VAPID_PUBLIC_KEY`/`VAPID_PRIVATE_KEY`/`VAPID_SUBJECT` all-or-none (none = off, `push_public_key: null` in `/api/config`); boot fails on a partial set, a public key that isn't a base64url uncompressed P-256 point, a private key that doesn't derive it, or a subject other than `mailto:<user>@<domain>`/`https://<domain>` (`core/push_keys.py`). `push_subscriptions` = one row per endpoint (UNIQUE, re-registration by another user moves it), max 20/user with least-recently-seen eviction on `PUT /api/me/push-subscriptions`; the endpoint is a capability URL, never logged. Sender `services/web_push.py`: fire-and-forget task scheduled by `create_share` after commit, semaphore (4) + pending cap (256, beyond = `dropped`), own DB sessions, one shared aiohttp client created/closed in the lifespan with redirects refused, push-service host allowlist (`PUSH_SERVICE_HOSTS`) enforced at `PUT` and again at send; 404/410 prunes the row (kept if under 60 s old: FCM 410s brand-new subscriptions), no retry, metric `inkwest_push_sent_total{result}`. SW `frontend/public/sw.js` (no-cache, no SPA fallback) skips the notification when an Inkwest window is focused; click focuses one or opens `/`. The browser prompt only follows a click (opt-in banner `PushOptInBanner` with a 30-day per-browser snooze, invite-popup link, Settings "Notifications" tab; shared state in `hooks/usePushOptIn.ts`), all hidden when `push_public_key` is null; on load the client re-`PUT`s / resubscribes on a key change; logout unsubscribes + `DELETE`s (2s cap). No cross-request state, so no single-replica constraint. See `docs/WEB_PUSH.md`
- **Announcement banners** (spec 004): `announcements` table, `GET /api/announcements` (any signed-in user, enabled + unexpired, no author) + admin CRUD `/api/admin/announcements` in `routes/announcements.py`; each committed write broadcasts `announcements_changed` (`user_id=None`, best effort, like `mcp_catalog_changed`). Front: `store/announcements.ts` (`refresh()` never throws, keeps previous items on failure, sequence-guarded against out-of-order responses) feeds `AnnouncementBanners` in `ShellLayout` after `UpdateBanner` (chat + admin console); per-browser dismissal in localStorage `inkwest.announcements.dismissed.v1` (`id:updated_at` keys, pruned to the served set once loaded); an expiry timer withdraws a banner at `ends_at` without a refetch; inline markdown only (strong/em/code/a/del, http(s)/mailto links). Refresh triggers: mount and `visibilitychange` to visible (in `AnnouncementBanners`), the admin console's own successful writes, and in `useSyncSocket` the `announcements_changed` frame (early return, no session refetch) plus every `onopen`; the console has no sync socket, so another admin's edit reaches it when the tab becomes visible again, on its own next write, or on re-entering the console. Admin page `/admin/announcements` (`AnnouncementsPage`, `useAnnouncementAdminStore`): list (author mapped via `useUserStore`: "deleted user" when `created_by` is null, short id when unknown) + modal form whose live preview is the same `AnnouncementBar` the stack renders (`decorative` in the console: no live region, close glyph aria-hidden; preview trimmed like the server and `inert`; colors in `lib/announcementColors.ts`). One write in flight at a time: Add/Edit disabled, the form cannot close until it settles, and the focused switch/Delete/submit go `aria-disabled` (not `disabled`, which drops focus). `datetime-local` sent as an aware UTC ISO (an untouched value resends the stored one, seconds kept); a 422 lists pydantic `loc: msg` in the open form. A successful write reloads the list and calls the banner store's `refresh()`; a failed one reloads the list only; the list also refetches when the tab becomes visible
- **Context pressure & compaction** (`specs/006-context-pressure.md`): occupancy of the model's context is the last assistant row's `input_tokens + cache_read_tokens + cache_write_tokens` (all input-side, wire-reported by all three engines) over the model's window — no tokenizer, no `count_tokens`, so the gauge lags one turn and self-corrects when an engine compacts behind our back. The window comes from a **sourced static table** (`context_window.py`, keyed like `pricing.price_match_keys`) + a `model_registry` `options.context_window` override; unknown ⇒ `None` ⇒ no gauge and (phase 3) never an automatic compaction — never act on a guessed window. `/api/config` ships it on `ModelInfo`; `lib/contextUsage.ts` is the pure client-side computation behind the header `ContextGauge` and the composer-toolbar `CompactContextButton` (offered past 75% of a known window, or past an absolute 150k prompt when the window is unknown; hidden while streaming and once nothing sits after the boundary). **Compaction** (`compaction.py`, WS `compact` → `start_gated_turn`, **owner-only**) is a boundary, not a deletion: dump the pre-boundary transcript to `/workdir/.inkwest/history-<n>.md` (via `sandbox.publish_workdir_file` — symlink-safe via `O_NOFOLLOW` dir fds, the sandbox writes to that volume; ~4 Mi-char cap), run one **normal billed turn** on the session's own engine with `get_compaction_prompt()`, then commit a `role='system'` boundary row (`save_session_event(subject='context', action='compacted', payload={summary})`, `strict=True`). From there `get_session_messages` replays only post-boundary rows (sliced by row **index**, then `merge_consecutive_roles()` so Converse's alternation survives the cut) and `with_compaction_summary()` appends the summary + archive path to each orchestrator's **assembled** system prompt, fenced as `<compaction_summary untrusted="true">` and capped (model-authored text must not gain system authority). Ordering is load-bearing: the turn's terminal `done` is **buffered** until the boundary commits (`turn_runner` frees the session slot on `done`), the summary is extracted only from rows *that turn* created (id watermark — a stale earlier row would silently become the new memory), and a turn that errors/cancels/produces no text writes **no boundary** and rolls back its rows + archive (a blank summary boundary = amnesia). Compaction clears `sessions.cli_session_id` (the CLI freezes its system prompt per session) and resets the opencode store; peers learn about it through a `context_compacted` ChatEvent, not pubsub (`save_message` has no notify). Phase 3 (auto-compaction on percent / rounds / absolute-token triggers) is **not implemented**

MCP credential brokering: static catalog HTTP/SSE servers (`mcp_catalog.py`) are rewritten to `/api/mcp-proxy/{key}/` + an internal JWT (like OAuth2) by `mcp_config.build_session_static_servers`, so their real headers/apikey never enter the sandbox — `mcp_proxy.py` injects them server-side; stdio servers can't be brokered (local process) and stay verbatim.
