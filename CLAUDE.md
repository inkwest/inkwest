# Inkwest

AI-powered investigation assistant — chat interface backed by Claude that brokers scoped, read-only access across connectors (Kubernetes/kubectl, AWS, GitLab) plus Coralogix observability via MCP, to investigate and correlate issues across systems.

## Tech Stack

- **Backend**: FastAPI + SQLAlchemy async + PostgreSQL + asyncpg
- **Frontend**: React + TypeScript + Vite + Zustand + Tailwind CSS
- **AI**: Claude Code CLI + sandboxed inkwest-agent (Bedrock Converse) + sandboxed opencode CLI; engine-dispatched, no `AI_PROVIDER`
- **Auth**: OIDC (optional) with JWT session tokens, dev mode auto-login

## Architecture

- **Orchestrator pattern**: each engine has its own orchestrator yielding `ChatEvent` for WS streaming; `get_orchestrator()` is a single per-turn engine dispatcher (no `AI_PROVIDER` — engine is the sole driver)
- **Cancellation**: orchestrators accept `cancel_event: asyncio.Event` checked at loop boundaries (before API call, after response, before/during tool execution)
- **Dependency injection**: FastAPI `Depends()` for `get_current_user`, `require_admin`, `get_db`, `check_cluster_access`
- **Real-time sync**: PostgreSQL `LISTEN/NOTIFY` → `pubsub.py` → per-WS `asyncio.Queue` fan-out
- **Tool execution**: async subprocess kubectl with validation, timeout, output truncation
- **WS dual-task pattern**: `chat.py` runs receive loop + process loop as concurrent tasks so `stop` messages arrive during streaming
- **Model selection**: admin-managed registry (`model_registry` table + `model_registry.py`) over a live-discovered catalog. `model_catalog.py` is pure discovery (Anthropic API, Bedrock via aws CLI incl. open-weight models when the `bedrock_include_open` flag is set; the CLI's backend is resolved from **backend settings** — `aws_bearer_token_bedrock`/AWS creds ⇒ Bedrock, else `anthropic_api_key` ⇒ Anthropic — never `sandbox.env`, so the LLM broker can strip the key from the sandbox without breaking discovery) with pricing resolved per turn as **live Bedrock Price-List → static table → default** (`pricing.get_model_pricing`): `pricing_live` fetches the public, unauthenticated AWS bulk Price List at catalog-refresh and maps it to model IDs via `pricing.price_match_keys`; the static table covers Anthropic (absent from the Bedrock Price List) and is the offline fallback. Vendor grouping/routing tags come from `model_catalog.bedrock_vendor` (the namespace, verbatim — no allowlist). The registry owns the admin-facing layer: which models are enabled, the default, per-model metadata (endpoint/arn/options), and pricing overrides, plus operator-added `source='custom'` rows the discovery filter doesn't surface. Discovered models with no row are synthesized on read (disabled; provider re-derived from the ID, priced when the live list or static table knows them). Resolution per turn: session pin → registry default → newest enabled → newest available, each validated against the current catalog so a backend/catalog change degrades gracefully. Admin endpoints: `/api/admin/settings/model` (GET/PUT) + `/api/admin/settings/model/refresh`, and the sibling `/api/admin/models` CRUD (`POST`, `PUT|DELETE /{model_id}`). Registry + catalog cached in-process (mirrored in memory post-write, like `app_settings.py`): replicas pick up changes on restart/TTL only. Switching a session's model invalidates its Anthropic prompt cache (first turn after re-pays full input)
- **Non-Anthropic Bedrock models in chat**: non-Anthropic Bedrock models (Llama/Mistral/Nova/DeepSeek) can't go through the Anthropic SDK, so they run on the **`inkwest-agent`** engine — the sandboxed worker's Bedrock **Converse** loop (`inkwest_agent/converse.py` + `loop.py`, boto3, translating Anthropic content blocks ↔ Converse blocks at the API boundary only). `get_orchestrator()`'s per-turn dispatcher (`ai_client._dispatch_engine`) resolves the engine via `engines.engine_for_turn` from the resolved model's registry provider tag (`provider_speaks_messages()` → Claude on the CLI; every other per-vendor tag → the agent), falling back to the `is_anthropic_model` ID heuristic for models with no registry row. Registry provider tags are per-vendor (`anthropic`/`amazon`/`meta`/`mistral`/`cohere`/`ai21`/`deepseek`/`stability`, derived via `model_catalog.bedrock_vendor`; legacy `bedrock`/`bedrock-open` still accepted). The whole-Bedrock catalog (all vendors) and the admin all-vendors toggle are gated on **any agent engine** (`inkwest-agent` or `opencode`) being enabled (`AGENTIC_ENGINES` → `engines.open_catalog_enabled()`, see `app/services/engines.py`). A second agent engine, **`opencode`**, runs the [opencode](https://opencode.ai) terminal coding agent non-interactively in the sandbox (`orchestrator_opencode.py`, `ai_cli_client.execute_opencode`/`parse_opencode_response`) — parity with `claude-cli` (spawn → NDJSON→`ChatEvent` → resume via `--continue` over a per-conv data-dir mount), giving native bash/file tools over Bedrock all-vendors, with MCP (→ `opencode.json` `mcp`) + skills (→ `AGENTS.md` index) materialized per turn and an abnormal-exit container teardown to reap child processes
- **LLM auth broker** (`llm_broker_enabled`, sandboxed engines): zero real Bedrock secret in the sandbox. The sandbox holds only a short-lived, opaque **per-turn grant** in `AWS_BEARER_TOKEN_BEDROCK` (in-process store `llm_proxy_token.py`, minted at turn start, BURNED in the orchestrator `finally`). The broker route `app/api/routes/llm_proxy.py` has two legs: data plane (`POST /api/llm-proxy/model/{id}/{op}`) verifies the grant, restricts to enabled registry models/ARNs (+ their inference-profile ids) + allowed Bedrock ops — **fail-closed**: no enabled rows ⇒ nothing invocable (unlike the default-open picker; the broker is a credential gate) — swaps in the backend-held real bearer (`settings.aws_bearer_token_bedrock`), streams to `bedrock-runtime.<region>` under a total wall-clock cap; control plane (`GET /api/llm-proxy/{inference-profiles|foundation-models}`, dot-segments rejected) forwards to `bedrock.<region>` so Claude Code can resolve a model to its regional inference profile (required in regions like eu-west-1 — without it the bare-id invoke 403s). Pure header swap, no SigV4 (both the CLI's `ANTHROPIC_BEDROCK_BASE_URL` and the agent's boto3 `endpoint_url` send `Authorization: Bearer …`; `x-amz-*` SigV4/credential headers from the sandbox are stripped); shared streaming-proxy primitives (body cap, hop-by-hop strip, teardown) live in `app/api/routes/_proxy_stream.py`, reused by `mcp_proxy.py`. Wiring (`llm_broker.py`): all sandboxed engines (CLI, inkwest-agent, opencode) inject the grant per turn via `docker exec -e` (overriding `sandbox_env_file`), each carrying the base URL its own way — the CLI via `ANTHROPIC_BEDROCK_BASE_URL`, the inkwest-agent via `bedrock_endpoint_url` on the TurnSpec (protocol v5; the orchestrator omits unset/None scalars from the wire spec so an older agent image still parses a broker-off turn), opencode via its `opencode.json` `provider.amazon-bedrock.options.baseURL`. With the broker on, the CLI is forced onto the registry default when a session has no model pin (else it'd invoke its built-in default and 403). Reuses the `mcp_proxy_base_url` host (squid allowlist + `--add-host`) — no new egress rule. Grant store is in-process + hard-capped (single-replica assumption; `main.py` fail-fasts on `WEB_CONCURRENCY>1`). Off by default ⇒ today's behavior (real bearer in `sandbox_env_file`). See `docs/llm-auth-broker.md`
- **MCP per-tool permissions**: engine-agnostic moderation at the proxy (`mcp_proxy.py` — all three engines' MCP traffic funnels there; `--dangerously-skip-permissions` stays, it governs built-in tools only). Policy = scope (global `user_mcp_tool_policy` / conversation `session_mcp_tool_policy`, `tool='*'` row = server default) × verdict (allow/deny/ask); `mcp_policy.resolve_verdict` precedence conv/tool → conv/* → global/tool → global/* → **ask** (system default). The proxy parses JSON-RPC `tools/call` (single + batch), denies with a -32001 JSON-RPC error, and on `ask` **holds the request** on an in-process Future (`mcp_ask_store.py`, 60s → deny, fail-closed, single-replica like `llm_proxy_token`): targeted WS frame `mcp_tool_ask` to the asking user's tabs only (`chat.send_to_user_in_session` — peers/guests never see it), decision via `POST /api/mcp/ask/{ask_id}`, reload-rehydrate via `GET /api/mcp/ask/pending`, `mcp_tool_ask_resolved` clears other tabs; a late Allow is dropped if the sandbox client already disconnected (no behind-the-back execution). Policy resolution failure fails OPEN (credential broker stays the hard boundary) but the ask flow fails CLOSED. Tool lists enumerated server-side (`mcp_tools.py`, mcp SDK is a core dep — image rebuild on deploy) into `mcp_server_tools` cache, `GET /api/mcp/{key}/tools` (+`?refresh`); UI = 5-option editor (`McpToolPolicyEditor`, conversation popup + Settings `mcp` tab, optimistic writes) + in-bubble ask decisions: a held call renders an Allow/Deny **split-button bar inside the matching transcript `ToolCallCard`** (scopes once / this conversation / always-global; broader scopes fetch→merge→PUT the per-server full-state policy through the shared `runPolicySave` chain in `store/mcpPolicy.ts`, then bump `useMcpPolicyVersion` so open editors refetch; the ask frame carries `session_id` so a conversation-scope write targets the ask's own session). Cards claim asks via a **per-card sync ref** (`useRef`) + store `claimedAsks` (state there loops: claim→release ping-pong ⇒ white page); `McpAskNotice` inline banner stack (tool name only — args already visible via tool_start) is the **fallback** for asks with no visible card (mid-hold reload) and rehydrates on mount/session-switch/WS-reconnect
- **Combined prod image**: root `Dockerfile` builds the SPA (`VITE_API_URL=""` → same-origin) and bakes it into `/app/static`; `mount_spa()` in `app/main.py` serves it with index.html fallback (404-guarded for `api/`, `assets/`, `ws/`), `Cache-Control: no-cache` on index, gzip + security headers. Dev unchanged (no `static/` dir → JSON root endpoint). CI builds it, no variants
- **Frontend backend-down resilience**: AWS/ALB answers 502/503/504 (or the network fails) while the backend restarts/redeploys. `services/api.ts::fetchWithRetry` (every `fetchAPI` caller + the raw attachment fetches route through it) retries those + network errors for **all verbs** with jittered capped-exponential backoff (`lib/backoff.ts::jitteredBackoff`, ~12 attempts ≈ up to a minute). Client timeouts split by idempotency: **GET/HEAD** get a 30s abort-**and-retry** timeout (a hung read is safe to replay); **mutations** get a 5min timeout-to-**fail** (`MUTATION_TIMEOUT_MS` — reject, never replay) so a slow AWS enumerate/STS-mint isn't killed but a truly hung POST still surfaces. Attachment transfers opt out of timeouts entirely. The three WS reconnect loops (`ChatWebSocket`, `useSyncSocket`, `useEgressSocket`) reconnect **uncapped** (delay capped 30s + jitter) until a 10min wall-clock budget (`lib/backoff.ts::createReconnectBudget`, reset on a successful open / tab-foreground) is spent; each stops on its own terminal/clean close codes (1000 app-close; 4001 auth→redirect; chat 4004/4010/4011; egress 4003) and aborts its in-flight `fetchWsTicket` on disconnect/unmount. A refcounted `store/backend.ts::useBackendStore` drives `BackendBanner`: amber "reconnecting…" while any HTTP call backs off (cleared on the first reachable app response or WS `onopen`), and — only when the **sync** socket (the app-wide heartbeat) exhausts its budget — a red **"reload"** prompt (`gaveUp`, sticky until page reload; chat/egress give up quietly). **Trade-off**: a retried non-idempotent call (502/504/network) can rarely double-apply server-side — accepted; durable fix is server idempotency keys on the AWS mint/grant routes. **Single connectivity surface**: `BackendBanner` is the *only* connectivity message (precedence `gaveUp` red-reload > `unavailable` amber). The chat header `ConnectionStatus` is the lone chat-scoped indicator — an icon-only dot (`title`/`aria-label`, non-live) that **yields** to the banner: while `unavailable || gaveUp` it shows a neutral dot instead of echoing "reconnecting"/"disconnected", surfacing the chat-socket state on its own only when the backend is up but the stream blipped. The in-view `ReconnectingBanner` was removed as a pure duplicate of that badge's `isReconnecting` flag. The banner additionally hosts a **non-connectivity surface**: a dismissible red **5xx strip** — `fetchAPI` (+ the raw attachment fetches) reports any app-emitted ≥500 (gateway 502/503/504 excluded, even after retry exhaustion — that's the amber banner's story) to `store/backend.ts::serverErrors` before throwing, deduped by `METHOD /path` with UUID path segments collapsed to `:id`, capped at `MAX_SERVER_ERRORS` (oldest evicted), self-healing on the route's next 2xx, so best-effort `catch {}` callers can't bury a persistent backend bug

## Key Directories

```
backend/app/api/routes/     # FastAPI route handlers
backend/app/api/dependencies.py  # Auth + DB injection
backend/app/services/       # Orchestrators, AI client, tools, budget; agent_mcp_config.py (P1.7: broker materializes a conversation's enabled MCP server defs into a sandbox file, removed on turn end as it can embed creds). MCP credential brokering: static catalog HTTP/SSE servers (`mcp_catalog.py`) are rewritten to `/api/mcp-proxy/{key}/` + an internal JWT (like OAuth2) by `mcp_config.build_session_static_servers`, so their real headers/apikey never enter the sandbox — `mcp_proxy.py` injects them server-side; stdio servers can't be brokered (local process) and stay verbatim. Needs `mcp_proxy_base_url`; unset ⇒ verbatim fallback
backend/app/models/         # SQLAlchemy models
backend/app/core/           # Config, auth, database, logging
backend/app/tools/          # kubectl definitions, executor, validation
backend/inkwest_agent/      # standalone agent worker (P1.1): DB-free Converse loop + stdin turn-spec -> stdout NDJSON ChatEvent (`python -m inkwest_agent`). P1.7: skills-as-tools (skills.py — synthetic `read_skill` progressive disclosure) + a lazy in-sandbox MCP client (mcp.py — connects enabled servers, merges their tools as `mcp__<server>__<tool>`; optional `mcp` SDK, degrades if absent)
frontend/src/components/    # React components (chat/, session/, layout/)
frontend/src/store/         # Zustand stores (chat, sessions, settings)
frontend/src/services/      # API client, WebSocket service
frontend/src/hooks/         # useWebSocket, etc.
```

## Testing

- **Backend**: pytest + pytest-asyncio. Mock DB via `AsyncMock(spec=AsyncSession)`, mock auth via `app.dependency_overrides`. API tests use `httpx.AsyncClient` + `ASGITransport`.
- **Frontend**: Vitest + React Testing Library. Mock `fetch` for API tests, Zustand `setState` for store tests.

| Mode | `OIDC_ENABLED` | Behavior |
|------|----------------|----------|
| Dev | `false` | Auto-creates `dev@localhost` admin user |
| OIDC | `true` | Standard OAuth2 code flow + JWT sessions |
