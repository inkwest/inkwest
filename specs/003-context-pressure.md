# 003 — Context pressure: gauge, warning, compaction with a grep-able archive

**Status**: draft
**Requested by**: @babs
**Date**: 2026-07-28
**Depends on**: nothing (branched off `develop`; `001`/`002` live on another branch — renumber if they land first)

## Problem

A long investigation silently walks into the model's context window. Nothing in Inkwest measures it:
the token badges in the header and the sidebar show **cumulative session spend**
(`total_input_tokens` + cache), which only ever grows and says nothing about how full the current
prompt is. The user finds out when a turn degrades — the model forgets the beginning of the
investigation — or when the provider rejects the request outright.

Two engines paper over it in ways we neither control nor observe: `claude-cli` auto-compacts on its
own schedule, `opencode` keeps its own session store. `inkwest-agent` truncates blindly by **message
count** (`truncate_messages(max_conversation_messages)`) — a window that has no relation to tokens,
so it drops turns that would have fit and keeps turns that don't.

And when the context does have to be reclaimed, everything before the cut is gone from the model's
reach, even though every message is still sitting in Postgres.

## Solution

Three parts, one release.

1. **Measure.** The prompt size of a turn is already persisted per assistant row:
   `input_tokens` (fresh) + `cache_read_tokens` + `cache_write_tokens` — all input-side, wire-reported
   by all three engines. That sum over the last assistant row **is** the context occupancy, and it
   self-corrects: when the CLI auto-compacts, the next turn's prompt is smaller and the gauge drops.
   Divided by the model's context window it becomes a percentage the user can see.

2. **Warn, then compact.** Past a warn threshold the header gauge turns amber and offers
   "Compact context". Past a trigger the next turn is preceded by an automatic compaction, announced
   in the transcript — the user is told, never surprised by a silently shortened memory.

   The trigger is a single pure function over three signals, any of which fires (each disablable):
   **percent of window**, **rounds since the last boundary**, and an **absolute prompt-token
   ceiling**. Percent alone is a bad cost guard: on a 300k (Nova) or 1M (Sonnet 1M) window, 90% is a
   fortune per turn, and every subsequent turn re-pays it — a long conversation costs the *sum* of its
   growing prompts, so the price of not compacting grows quadratically in rounds. The round counter
   and the token ceiling bound that independently of how large the window happens to be. A floor
   (`min_percent`) keeps the round counter from firing a compaction on a context that is still small,
   which would cost a full-context turn to reclaim nothing.

3. **Compact without losing anything.** Compaction is a **boundary**, not a deletion: a summary turn
   is generated by the session's own engine, a `role='system'` marker row records the cut, and the
   transcript replayed to the model starts after it. The full pre-boundary transcript is dumped to
   `/workdir/.inkwest/history-<n>.md` in the conversation's own workdir, and the summary tells the
   model that file exists. Recall then costs nothing new: every engine already has file/grep tools
   over `/workdir` (CLI `Read`/`Grep`/`Bash`, opencode natively, `inkwest-agent` via
   `exec.read_file`/`bash`). No new tool, no new MCP server, no new permission surface.

The DB keeps every row, so the UI still renders the whole conversation and undoing a compaction is
deleting one marker row.

## Scope

- `context_window` resolution: static per-model table + `model_registry` `options.context_window`
  override; unknown ⇒ `null` (no gauge, no auto-compaction — never act on a guessed window).
- `context_window` exposed on `AppConfig.available_models[]` (`/api/config`).
- Header gauge (% of window, amber past warn, red past compact threshold) + a "Compact context"
  action; pure client-side computation from the last assistant row + the resolved model.
- WS `compact` message type (owner/editor only, rejected while a turn is active), running one turn
  through the session's resolved engine with a new `COMPACTION_PROMPT`.
- Boundary row: `role='system'`, `content = {event: 'context_compacted', summary, message_count,
  archive_path}` — reuses the existing session-event rendering for the transcript divider.
- `get_session_messages` returns only rows **after** the last boundary; new
  `get_compaction_summary()` injected into the system prompt of all three orchestrators.
- Engine resume handles reset on compaction: `sessions.cli_session_id = NULL`; opencode's `resume`
  falls to `False` on its own (its history query returns empty post-boundary); `inkwest-agent` has
  no handle.
- Archive dump to `/workdir/.inkwest/history-<n>.md` (markdown, one section per message) + the
  summary naming the path.
- Auto-compaction before a user turn past the trigger, with a visible notice naming which signal
  fired; admin settings `context_autocompact_enabled` (default true), `context_warn_percent`
  (default 75), and the trigger set — `context_compact_percent` (default 90),
  `context_compact_rounds` (default 40, counted since the last boundary),
  `context_compact_prompt_tokens` (default 200000, absolute ceiling — the cost guard for large
  windows), `context_compact_min_percent` (default 25, floor below which nothing auto-compacts).
  Each trigger disabled by setting it to 0/null.
- One pure `context_pressure.should_compact()` over `(prompt_tokens, window, rounds_since_boundary)`
  returning the firing signal or `None` — the backend is the sole decision authority; the frontend
  only renders the gauge and its amber/red colour.
- Broadcast: existing pubsub `notify` on the boundary row so every participant's transcript shows it.
- `pytest` + `vitest` coverage per phase; `docs/` update (BUDGET.md cost note, ARCHITECTURE.md).

## Out of scope

- Token counting we do ourselves (no `count_tokens` call, no tokenizer in-process). The wire-reported
  usage of the previous turn is the measurement; a brand-new session shows no gauge until its first
  assistant row lands. Accepted: the gauge is one turn behind.
- Semantic recall (embeddings, pgvector, a `search_history` tool). Grep over the archive file is the
  recall mechanism.
- Replacing `truncate_messages`' message-count window with a token-based one. Compaction makes it
  rarely reachable; changing both at once muddies the blast radius.
- Disabling the CLI's own auto-compaction (not exposed). Ours triggers earlier; both can coexist.
- Per-session or per-user opt-out of auto-compaction (one deployment-level flag; add when asked).
- A **cost-based** trigger (cumulative USD since the last boundary). It is the most faithful proxy for
  "this is getting expensive" and is computable from the post-boundary rows' stamps ×
  `pricing.get_model_pricing`, but it is a fourth comparison inside the same `should_compact()` — add
  it there if the round counter proves too coarse. Rounds ship first because they need no pricing
  lookup and are what the user can reason about.
- A cooldown between compactions. Unnecessary by construction: the round counter and the summary both
  restart at the boundary, and `min_percent` blocks a second reclaim of an already-small context.
- Compacting mid-turn. A running turn is never interrupted for context reasons.
- Forking a compacted conversation into a new session (explicitly considered, dropped — see
  Decisions).

## Acceptance criteria

- [ ] Given an assistant row with `input_tokens=5000`, `cache_read_tokens=120000`,
      `cache_write_tokens=3000` and a 200k-window model, then the gauge reads 64%.
- [ ] Given a model whose context window is unknown, then no gauge is rendered and auto-compaction
      never triggers for that session.
- [ ] Given a model registry row with `options.context_window = 500000`, then that value wins over
      the static table.
- [ ] Given usage past `context_warn_percent`, then the gauge is amber and the "Compact context"
      action is offered; past `context_compact_percent` it is red.
- [ ] Given a `compact` WS message from a viewer, then it is rejected like `message`/`retry`/`stop`.
- [ ] Given a `compact` while a turn is active, then it is refused (one turn per session) and the
      running turn is untouched.
- [ ] Given a compaction on a session with N messages, then: a summary assistant bubble is persisted,
      a `context_compacted` system row follows it, `get_session_messages` returns `[]` for that
      session, and `sessions.cli_session_id` is `NULL`.
- [ ] Given a compacted session, when the next turn runs, then the system prompt contains the summary
      and the archive path, and the transcript sent to the model contains only post-boundary rows.
- [ ] Given a compacted session, then `/workdir/.inkwest/history-1.md` exists in that conversation's
      workdir and contains the pre-boundary messages; a second compaction writes `history-2.md` and
      leaves the first intact.
- [ ] Given two compactions, then only the **last** boundary is applied when building the transcript
      (the summary of the second supersedes the first).
- [ ] Given a compacted session, when the UI reloads, then the full history renders with a divider at
      the boundary — no message disappears from the transcript.
- [ ] Given `context_autocompact_enabled=false`, then crossing any trigger warns but never compacts.
- [ ] Given 40 rounds since the last boundary at 60% of window, then the round trigger fires (percent
      alone would not have).
- [ ] Given 40 rounds since the last boundary at 12% of window (`min_percent=25`), then nothing
      compacts — the floor wins over the round counter.
- [ ] Given a 1M-window model at 21% (210k prompt tokens) and `context_compact_prompt_tokens=200000`,
      then the ceiling fires even though the percent trigger is far away.
- [ ] Given each trigger set to 0, then it never fires and the others still do.
- [ ] Given a compaction, then the round counter restarts at 0 (counted from the last boundary row),
      so no second compaction can chain onto the first.
- [ ] Given an auto-compaction, then the system row and the UI notice name which signal fired
      (percent / rounds / token ceiling).
- [ ] Given auto-compaction fires, then a system row records that it was automatic and the user's
      queued message runs on the compacted context.
- [ ] Given a compaction turn, then its tokens are metered like any turn (broker row or engine row —
      no accounting hole) and the session's cache-read on the following turn is ~0 (prefix changed).
- [ ] Given a shared conversation, when one participant compacts, then the others receive the
      boundary row over the sync socket without reloading.

## Phases

### Phase 1 — Measure and show
- Work: `app/services/context_window.py` (static table keyed like `pricing.price_match_keys`, +
  registry `options.context_window` override, `None` when unknown); `context_window` on `ModelInfo`
  in `/api/config`; `frontend/src/lib/contextUsage.ts` (pure: last assistant row + window → percent);
  gauge in `components/layout/Header.tsx` next to the existing token badge. The gauge's two
  **colour** thresholds are client-side constants in `contextUsage.ts` for this phase — the
  server-side ones only exist from phase 3, and they gate an action, not a colour.
- **Data model impact**: none (registry `options` is already JSONB).
- **DoD**: `pytest tests/test_context_window.py tests/test_api_config.py -q` green, including an
  unknown-model case returning `None` and an `options` override winning;
  `npx vitest run src/lib/contextUsage src/components/layout` green with the 64% case above and the
  "no window ⇒ no gauge" case; `npm run lint`, `npx tsc --noEmit` clean. Sources for every static
  window value cited in the module docstring — no invented number.

### Phase 2 — Manual compaction + archive + boundary
- Work: `COMPACTION_PROMPT` replacing the dead `SUMMARY_PROMPT`/`get_summary_prompt` (structured:
  goal, established facts, ruled-out hypotheses, current state, next step, and the archive path);
  `compact` WS type wired to `turn_runner` with `persist_user_message=False`; boundary row writer +
  archive dump helper; `get_session_messages` slicing after the last boundary +
  `get_compaction_summary()` injected into the three orchestrators' system prompts;
  `cli_session_id` reset; `SessionEventContent` rendering for `context_compacted`; the header action
  wired to the WS.
- **Data model impact**: none — the boundary is a `messages` row with `role='system'` (already
  excluded from the model transcript, already rendered as an event line).
- **DoD**: `pytest tests/ -q` green with tests for (a) slicing at the last of two boundaries,
  (b) the summary reaching each orchestrator's system prompt, (c) viewer rejection, (d) refusal while
  a turn is active, (e) the archive file written under the conversation workdir; `npx vitest run`
  green on the divider + the action; removing the slice makes (a) red (verify).

### Phase 3 — Auto-compaction on the trigger set
- Work: pure `should_compact()` over percent / rounds-since-boundary / absolute token ceiling, with
  the `min_percent` floor. Its `prompt_tokens` comes from the turn's **`usage_records` row** (the
  authoritative accounting row, broker or engine), *not* the `messages` token stamp: the stamp is
  display-only and its write failure is swallowed (`turn_usage.py`), which would silently stop
  auto-compaction. The gauge keeps reading the stamp — a stale gauge is cosmetic. Rounds counted
  from the last boundary row (one COUNT, no new column);
  pre-turn check in the WS `message` path (compaction runs first, then the user's turn) gated on
  `context_autocompact_enabled` and a known window; admin settings + System Info line; system row
  marking the compaction automatic and naming the firing signal; UI notice.
- **Data model impact**: `app_settings` rows only (existing key/value store).
- **DoD**: `pytest tests/ -q` green — table-driven test over `should_compact()` covering every
  trigger, the floor, each trigger disabled, and an unknown window; plus a test that a session past a
  trigger compacts before its next turn and does not when the flag is off; `vitest` green on the
  notice; `pre-commit run --all-files` clean; `docs/BUDGET.md` states the compaction turn is billed,
  invalidates the prompt cache, and explains why the round/token triggers exist.

Single MR for all three phases (requested): an alert with no escape hatch is a worse product than no
alert, and the auto path is what makes the feature survive a user who does not watch the gauge.

## Data model impact (summary)

- No migration. The boundary is a `messages` row (`role='system'`, structured `content`), the window
  override rides `model_registry.options` (JSONB), the thresholds ride `app_settings`.
- The archive file lives in the conversation's existing `/workdir` — same confidentiality class as
  attachments and tool output already stored there. No new egress, no upload.

## Open questions

- [ ] Static context-window values must be sourced per model from vendor docs (neither Bedrock
      `ListFoundationModels` nor Anthropic `/v1/models` returns a context length). Any model we
      cannot source stays `None`.
- [ ] Archive retention: the workdir is per-conversation and durable, so archives accumulate. Cap at
      the last N, or leave to the existing workdir lifecycle? Leaning: leave it, revisit if a
      conversation ever fills its volume.

## Decisions

- **Occupancy is measured from the last turn's reported prompt size** (the UI reads the per-message
  stamp, the auto-compaction decision reads the `usage_records` row — see phase 3), not counted locally — chosen
  because it is already persisted for all three engines, needs no tokenizer, and self-corrects when
  an engine compacts behind our back. Consequence accepted: the gauge lags one turn and reads nothing
  before the first assistant reply.
- **Boundary in place, not a fork into a new session** — chosen by @babs: the conversation
  stays one thread in the sidebar and the UI keeps rendering the whole history. Cost: three
  orchestrators must consult the boundary, versus zero code for a fork.
- **Recall via a grep-able archive file in `/workdir`, not a search tool** — chosen by
  @babs ("make the conversation available for search"). All three engines already have file
  and shell tools over that mount, so this ships as one file write instead of an internal MCP server
  plus a tool policy default (which would have defaulted to `ask`, i.e. a permission prompt on every
  recall).
- **Manual button *and* an automatic trigger with a visible warning** — chosen by @babs.
  The automatic path never fires mid-turn and always leaves a transcript row saying it happened.
- **A round counter and an absolute token ceiling sit beside the percent trigger** — asked for by
  @babs on cost grounds. Percent of window is a *capacity* signal, not a *price* signal:
  it lets a 1M-window model reach 900k tokens per turn before reacting, and every further turn pays
  that again. The three signals are three comparisons in one pure function, so the flexibility is
  ~free; the `min_percent` floor is the guard that stops the round counter from spending a
  full-context turn to reclaim a nearly-empty one.
- **The backend owns the decision, the frontend owns the gauge.** The thresholds are not
  re-implemented client-side: the UI colours the gauge from `warn_percent` and learns about a
  compaction from the transcript row, so there is one place where "should we compact" is decided.
- **`Session.confirmation_mode` / `cost_confirmation_threshold` /
  `iteration_confirmation_interval` are dead columns** (nothing reads them) — this feature does not
  revive or extend them. Deleting them is a separate cleanup.
- **Compaction is a normal, billed engine turn.** No hidden LLM path: it goes through the resolved
  engine, the broker, and the metering already in place. The user pays for the summary — stated in
  the UI action, not discovered in a usage report.
- **The summary is a visible assistant bubble**, not a hidden field: the user can read what the model
  will remember, and it lands in exports.
- **Never compact on a guessed window.** An unknown context window disables the gauge and the auto
  path rather than assuming 200k — over-compacting a 1M-window model silently destroys context the
  user paid to build.
