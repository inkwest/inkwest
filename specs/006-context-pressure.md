# 006 — Context pressure: gauge, warning, compaction with a grep-able archive

**Status**: in progress (phases 1-2 implemented, phase 3 not started)
**Requested by**: Damien Degois
**Date**: 2026-07-28
**Depends on**: nothing

## Problem

A long investigation silently walks into the model's context window. Nothing in Inkwest measures it:
the token badges in the header and the sidebar show **cumulative session spend**
(`total_input_tokens` + cache), which only ever grows and says nothing about how full the current
prompt is. The user finds out when a turn degrades — the model forgets the beginning of the
investigation — or when the provider rejects the request outright.

Two engines paper over it in ways we neither control nor observe: `claude-cli` auto-compacts on its
own schedule, `opencode` keeps its own session store. `inkwest-agent` truncates blindly by **message
count** (`truncate_messages(max_conversation_messages)`) — a window that has no relation to tokens,
so it drops turns that would have fit and keeps turns that don't.

And when the context does have to be reclaimed, everything before the cut is gone from the model's
reach, even though every message is still sitting in Postgres.

## Solution

Three parts, one release.

1. **Measure.** Each engine reports the prompt of the turn's **last** model call (fresh input +
   cache read + cache write, all wire-reported) as `context_tokens` on its terminal `done`, and the
   turn's assistant row persists it in `messages.context_tokens`. That value on the last assistant
   row that has it **is** the context occupancy. The row's `input_tokens` + `cache_read_tokens` +
   `cache_write_tokens` are not: they sum the prompt of every tool iteration of the turn, so a
   5-iteration turn over a 51k prompt reads ~128% of a 200k window for ~26% real occupancy. The
   reading self-corrects: when the CLI auto-compacts, the next turn's prompt is smaller and the gauge
   drops. Divided by the model's context window it becomes a percentage the user can see.

2. **Warn, then compact.** Past a warn threshold the header gauge turns amber and offers
   "Compact context". Past a trigger the next turn is preceded by an automatic compaction, announced
   in the transcript — the user is told, never surprised by a silently shortened memory.

   The trigger is a single pure function over three signals, any of which fires (each disablable):
   **percent of window**, **rounds since the last boundary**, and an **absolute prompt-token
   ceiling**. Percent alone is a bad cost guard: on a 300k (Nova) or 1M (Sonnet 1M) window, 90% is a
   fortune per turn, and every subsequent turn re-pays it — a long conversation costs the *sum* of its
   growing prompts, so the price of not compacting grows quadratically in rounds. The round counter
   and the token ceiling bound that independently of how large the window happens to be. A floor
   (`min_percent`) keeps the round counter from firing a compaction on a context that is still small,
   which would cost a full-context turn to reclaim nothing.

3. **Compact without losing anything.** Compaction is a **boundary**, not a deletion: a summary turn
   is generated by the session's own engine, a `role='system'` marker row records the cut, and the
   transcript replayed to the model starts after it. The full pre-boundary transcript is dumped to
   `/workdir/.inkwest/history-<n>.md` in the conversation's own workdir, and the summary tells the
   model that file exists. Recall then costs nothing new: every engine already has file/grep tools
   over `/workdir` (CLI `Read`/`Grep`/`Bash`, opencode natively, `inkwest-agent` via
   `exec.read_file`/`bash`). No new tool, no new MCP server, no new permission surface.

The DB keeps every row, so the UI still renders the whole conversation and undoing a compaction is
deleting one marker row.

## Scope

- `context_window` resolution: static per-model table + `model_registry` `options.context_window`
  override; unknown ⇒ `null` (no gauge, no auto-compaction — never act on a guessed window).
- `context_window` exposed on `AppConfig.available_models[]` (`/api/config`).
- Header gauge (% of window, amber past warn, red past compact threshold); pure client-side
  computation from the last assistant row's `context_tokens` + the resolved model. The "Compact context" action sits in
  the **composer toolbar**, not the header (see phase 2 for why).
- WS `compact` message type (**owner only** — an editor can drive a turn but not rewrite what the
  session remembers; rejected while a turn is active, and by the WS route itself when nothing
  follows the last boundary, before any turn starts: that check is an EXISTS query run after the
  rate gate and the active-turn check, so a burst of frames never loads the transcript), running one turn through the session's
  resolved engine with a new `COMPACTION_PROMPT`. The summary turn replays the engine's normal
  message window (no lifted cap: the turn must still fit the model when the conversation is at its
  largest); the prompt points it at this segment's archive file for whatever the window left out,
  and states the summary budget (`MAX_SUMMARY_CHARS`).
- Boundary row: `role='system'`, `content = {type: 'session_event', subject: 'context', action:
  'compacted', summary, targets: [{message_count, trigger, archive_path?}]}` — the existing
  session-event shape (`messages.session_event_content`, shared with `save_session_event`), so the
  transcript divider reuses the session-event rendering. It is
  committed in ONE transaction with `sessions.cli_session_id = NULL`: the CLI never replays the DB
  transcript, so either write without the other loses or replays the conversation. The
  `summary` is server-only: it is stripped before the row reaches any client (authenticated or
  public share link). A boundary row whose summary is missing or blank is **not** treated as a
  boundary — it would cut the transcript while injecting nothing, i.e. silent amnesia.
- `get_session_messages` returns only rows **after** the last boundary (rows ordered by
  `(created_at, id)` in every query that feeds the cut, sliced by row index, then
  `merge_consecutive_roles()` so the post-slice head can't break Converse's alternation); the
  summary block appended to the assembled system prompt of all three orchestrators
  (`with_compaction_summary()` for claude-cli and inkwest-agent; opencode fetches the boundary once
  with `last_boundary()` for its store check too and passes it to `append_compaction_summary()`).
- Engine resume handles reset on compaction, only once the boundary is committed (an abandoned
  compaction never touches engine state): `sessions.cli_session_id = NULL` in the boundary's own
  transaction, then opencode's on-disk session store is emptied in place
  (`sandbox.reset_opencode_store`) — `--continue` resolves against THAT store, not the DB, so a
  surviving store replays the transcript the boundary just cut. If `opencode.db` survives the reset
  it raises; the compaction stays committed and the failure is logged. Every opencode run that produced output records the boundary it ran under in
  `<session_dir>/opencode.boundary` (the session root, which is never bind-mounted, so the sandbox
  cannot forge it; written atomically). A turn whose current boundary differs from that record (a
  missing record matches only a never-compacted session) retries the reset and runs without
  `--continue`, whichever engine ran the turns in between.
- A boundary commit that raises is checked on a session of its own before anything is undone,
  the check and the undo under one shield. A commit the server applied is kept: after a lost ack
  the compaction finishes as a success (engine reset, `done`, divider); after a cancel the row and
  the cleared `cli_session_id` stay, the cancel is re-raised, no `done` or divider is sent, and the
  opencode reset is left to the sidecar check of the next opencode turn. A failing check deletes
  nothing and propagates.
  `inkwest-agent` has no handle. An engine that nonetheless starts a turn with an empty transcript
  (stale CLI `--resume`, missing store) reports it (`compaction.note_empty_replay`) and the
  compaction is abandoned rather than committing a "nothing to summarize" boundary. During a
  compaction the engine stops right there, before it spawns: a CLI session with no `cli_session_id`
  and an opencode conversation whose store is gone are refused at no cost.
- An abandoned compaction (engine error, blind engine, cancel, raise, boundary write failure)
  rolls back its rows and archive on its own DB session (the turn's may be in a failed flush, or
  closed by the runner after a second cancel), shielded from cancellation, then waives the runner's
  "turn aborted" marker (`turn_runner.skip_abort_marker`), so the conversation is left exactly as it
  was. A rollback that itself fails keeps the marker.
- When the sandbox is enabled but the archive could not be written even into a fresh directory
  this process creates (see below), the compaction is refused inside the turn before the engine runs (no tokens, no rows, no abort marker), whatever
  the segment's length: the agent loop re-truncates its message window after every tool round,
  which the compaction prompt invites, so any row can drop out of view mid-turn and the archive is
  the only place left to read it. Applied to every engine: predicting the dispatched engine would
  duplicate the dispatcher, and without the archive the recall path is gone for every engine.
  Without a sandbox there is no archive to write or read, and the compaction proceeds.
- Archive dump to `/workdir/.inkwest/history-<n>.md` (markdown, one section per message) + the
  system prompt naming the glob `/workdir/.inkwest*/history-*.md` (`_archive_hint()`: always true,
  whichever directories past segments landed in; the compaction prompt itself names this segment's
  file, and the boundary records it). `<n>` is one past the highest archive already in the chosen
  directory,
  not the boundary count: undoing a compaction (deleting its boundary row) keeps its archive, and
  the next one must not overwrite it. Written through `sandbox.publish_workdir_file` — staged outside the
  mount and hard-linked into place relative to a directory fd opened `O_NOFOLLOW` per segment,
  because the sandbox can write to that volume: a planted symlink would otherwise redirect the dump
  anywhere the backend can write, and a name-based check would still lose the race against a
  mid-write swap. `link` refuses an existing name, so an archive is never overwritten: a name taken
  after the index was read is skipped for the next one (bounded), and the boundary and the prompt
  record the path actually used. Nothing the sandbox may own is moved, renamed, chmod'ed or
  deleted: `.inkwest` is used whenever this process can link into it, whoever owns it (a root
  backend uses a sandbox-owned one); only a symlink, a file or a directory it cannot link into
  sends the archive to a fresh `.inkwest-<12 hex>` directory, built in the session root outside the
  mount and renamed into the workdir whole, so the sandbox never sees it empty (a taken name tries
  another, a few times; an empty directory raced in at that name may be replaced). A mode is
  forced only on a directory this call created. Removing an abandoned archive checks its inode, so
  a file the sandbox renamed over it survives.
  Every row is written in full, streamed block by block into the staging file; each content block
  is capped at ~200k characters (every block kind), which bounds memory to one block past the rows
  already loaded. No total cap: a row left out is a row nobody summarizes, and a total cap would
  make the largest segments uncompactable for good.
- Auto-compaction before a user turn past the trigger, with a visible notice naming which signal
  fired; admin settings `context_autocompact_enabled` (default true), `context_warn_percent`
  (default 75), and the trigger set — `context_compact_percent` (default 90),
  `context_compact_rounds` (default 40, counted since the last boundary),
  `context_compact_prompt_tokens` (default 200000, absolute ceiling — the cost guard for large
  windows), `context_compact_min_percent` (default 25, floor below which nothing auto-compacts).
  Each trigger disabled by setting it to 0/null.
- One pure `context_pressure.should_compact()` over `(prompt_tokens, window, rounds_since_boundary)`
  returning the firing signal or `None` — the backend is the sole decision authority; the frontend
  only renders the gauge and its amber/red colour.
- Broadcast: a `context_compacted` `ChatEvent` carrying the boundary row's id, timestamp and its
  persisted `content` (stripped of the summary), emitted by
  the orchestrator after the row commits and fanned out on the chat socket like any other turn event
  — `save_message` has no pubsub notify of its own, so without it a peer would only see the divider
  on reload.
- `pytest` + `vitest` coverage per phase; `docs/` update (BUDGET.md cost note, ARCHITECTURE.md).

## Out of scope

- Token counting we do ourselves (no `count_tokens` call, no tokenizer in-process). The wire-reported
  usage of the previous turn is the measurement; a brand-new session shows no gauge until its first
  assistant row lands. Accepted: the gauge is one turn behind.
- Semantic recall (embeddings, pgvector, a `search_history` tool). Grep over the archive file is the
  recall mechanism.
- Replacing `truncate_messages`' message-count window with a token-based one. Compaction makes it
  rarely reachable; changing both at once muddies the blast radius.
- Disabling the CLI's own auto-compaction (not exposed). Ours triggers earlier; both can coexist.
- Per-session or per-user opt-out of auto-compaction (one deployment-level flag; add when asked).
- A **cost-based** trigger (cumulative USD since the last boundary). It is the most faithful proxy for
  "this is getting expensive" and is computable from the post-boundary rows' stamps ×
  `pricing.get_model_pricing`, but it is a fourth comparison inside the same `should_compact()` — add
  it there if the round counter proves too coarse. Rounds ship first because they need no pricing
  lookup and are what the user can reason about.
- A cooldown between compactions. Unnecessary by construction: the round counter and the summary both
  restart at the boundary, and `min_percent` blocks a second reclaim of an already-small context.
- Compacting mid-turn. A running turn is never interrupted for context reasons.
- Forking a compacted conversation into a new session (explicitly considered, dropped — see
  Decisions).

      three engines (CLI: last top-level message, subagent messages excluded), while the cumulative
      counts stay cumulative.
- [x] Given assistant rows with no `context_tokens` (rows predating the column, an older agent
      image), then they are skipped, never summed; no gauge until a row after the last boundary

- [x] Given a model whose context window is unknown, then no gauge is rendered and auto-compaction
      never triggers for that session — but the manual action is still offered past an absolute

## Data model impact (summary)

- One migration: nullable `messages.context_tokens` (the last call's prompt). The boundary is a `messages` row (`role='system'`, structured `content`), the window
  override rides `model_registry.options` (JSONB), the thresholds ride `app_settings`.
- The archive file lives in the conversation's existing `/workdir` — same confidentiality class as
  attachments and tool output already stored there. No new egress, no upload.

## Open questions

- [ ] Phase 3's authoritative prompt size: the last broker `usage_records` row of the turn is per
      call, but the engine-side row (broker off) is cumulative. Either carry `context_tokens` on
      `usage_records` or accept the display stamp's failure mode.
- [ ] Static context-window values must be sourced per model from vendor docs (neither Bedrock
      `ListFoundationModels` nor Anthropic `/v1/models` returns a context length). Any model we
      cannot source stays `None`.
- [ ] Archive retention: the workdir is per-conversation and durable, so archives accumulate. Phase 2
      ships a per-block cap (~200k characters) but no per-file or count cap — the existing workdir
      lifecycle owns deletion. Revisit if a conversation ever fills its volume.

## Decisions

- **Occupancy is measured from the last model call's reported prompt size** (the UI reads the
  per-message `context_tokens` stamp; the auto-compaction source is open, see phase 3), not counted locally — chosen
  because it is already persisted for all three engines, needs no tokenizer, and self-corrects when
  an engine compacts behind our back. Consequence accepted: the gauge lags one turn and reads nothing
  before the first assistant reply.
- **Boundary in place, not a fork into a new session** — chosen by Damien Degois: the conversation
  stays one thread in the sidebar and the UI keeps rendering the whole history. Cost: three
  orchestrators must consult the boundary, versus zero code for a fork.
- **Recall via a grep-able archive file in `/workdir`, not a search tool** — chosen by
  Damien Degois ("make the conversation available for search"). All three engines already have file
  and shell tools over that mount, so this ships as one file write instead of an internal MCP server
  plus a tool policy default (which would have defaulted to `ask`, i.e. a permission prompt on every
  recall).
- **Manual button *and* an automatic trigger with a visible warning** — chosen by Damien Degois.
  The automatic path never fires mid-turn and always leaves a transcript row saying it happened.
- **A round counter and an absolute token ceiling sit beside the percent trigger** — asked for by
  Damien Degois on cost grounds. Percent of window is a *capacity* signal, not a *price* signal:
  it lets a 1M-window model reach 900k tokens per turn before reacting, and every further turn pays
  that again. The three signals are three comparisons in one pure function, so the flexibility is
  ~free; the `min_percent` floor is the guard that stops the round counter from spending a
  full-context turn to reclaim a nearly-empty one.
- **The backend owns the decision, the frontend owns the gauge** — the phase-3 target. Until the
  server-side thresholds exist, the gauge's two colours and the manual offer come from client
  constants in `contextUsage.ts` (`GAUGE_WARN_PERCENT`, `GAUGE_ALERT_PERCENT`,
  `COMPACT_OFFER_PERCENT`); they gate a colour and an affordance, never a spend. Phase 3 moves the
  "should we compact" decision server-side, where it belongs once it can act unprompted.
- **`Session.confirmation_mode` / `cost_confirmation_threshold` /
  `iteration_confirmation_interval` are dead columns** (nothing reads them) — this feature does not
  revive or extend them. Deleting them is a separate cleanup.
- **Compaction is a normal, billed engine turn.** No hidden LLM path: it goes through the resolved
  engine, the broker, and the metering already in place. The user pays for the summary — stated in
  the UI action, not discovered in a usage report.
- **The summary is a visible assistant bubble**, not a hidden field: the user can read what the model
  will remember, and it lands in exports. It is copied onto the boundary row so the replay logic has
  one row to read, and stripped from `MessageResponse` so the API doesn't ship it twice.
- **The summary is model-authored, therefore untrusted.** It is injected into the next turns' system
  prompt inside a `<compaction_summary untrusted="true">` fence and capped at 8000 chars (a budget
  the compaction prompt states, derived from the same constant): without the
  fence, anything a tool result talked the model into writing would be promoted to system-prompt
  authority for the rest of the conversation.
- **Compaction is owner-only**, though an editor can run turns. Compaction rewrites what the session
  remembers from here on; that is closer to deleting the conversation than to answering in it.
- **The turn's terminal event is held until the boundary commits.** `turn_runner` frees the session
  slot on `done`, so emitting it before the boundary write would let a racing turn start against a
  half-compacted session.
- **The archive keeps tool output verbatim** — that is the point of it: recall must reproduce what the
  investigation actually saw, and a summarised archive would just be a second lossy summary. It
  therefore holds the same secrets the transcript holds (kubectl/AWS output), in the same
  per-conversation volume as attachments and tool output. Contained by caps and by the workdir's
  existing lifecycle, not by filtering — recorded in `docs/credentials-at-rest-audit.md`.
- **Never compact on a guessed window.** An unknown context window disables the gauge and the auto
  path rather than assuming 200k — over-compacting a 1M-window model silently destroys context the
  user paid to build.
